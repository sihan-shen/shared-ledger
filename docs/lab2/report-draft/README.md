# 实验二报告草稿

- 正文：`实验二报告草稿.md`，以实验一需求列表 V0.3 为基线。
- PDF 预览：`output/pdf/实验二_软件设计与建模_草稿.pdf`，生成脚本 `build_report.py`。
- AI 使用证据：`AI辅助记录.md`；本人工作补录入口：`人工修订记录模板.md`。
- `assets/uml/`：原 `../uml/` 的 9 份 PlantUML 源文件快照及在本轮重新渲染的 PNG。
- `assets/ui/`：既有本地原型、Figma 截图和历史参考稿的报告用快照，不代表所有界面均已正式设计完成。
- `assets/evidence/`：方案、两份设计审查、原型说明与核验、Figma断点等9份证据快照；来源映射见 `素材来源.json`。

本报告是 AI 辅助草稿，保留“待本人确认”及“待补”内容。个人体验不可由模型代替填写；尚未完成的人工修改、设计工具操作、Git 提交、测试与验收不得改写为已完成。

PDF 正文使用 A4；信息密集的类图、组件图及长图使用较大技术图页，以便放大阅读，高清 PNG 与源文件仍随报告保留。当前手机长页在 PDF 展示首屏节选，完整截图在 `assets/ui/`。这份 PDF 侧重数字审阅，若最终要求统一 A4 打印，应先简化总览图并按领域拆分详图。

构建 PDF：

```bash
python3 build_report.py
```

需要 reportlab、Pillow，以及支持中文的 TrueType 字体；可通过 `REPORT_FONT_REGULAR` / `REPORT_FONT_BOLD` 指定字体。当前优先使用本机 Maple Mono 中文字体，脚本同时支持 Codex 自带 Python 运行时。

本轮在独立分支 `codex/lab2-report-draft` 记录一次 AI 辅助初稿。实验一标签与 master 保留。以后由本人阅读正文、核对图源和 UI 后，实际修改正文及 `人工修订记录模板.md`，再进行明确标记为人工修改的提交。不要只修改提交说明而没有实质内容差异。

正式提交前：补足本人反思和人工修订证据；确认课程对 UI 设计工具的要求；完善全模块界面；去除草稿标记；核对 PDF；再按 `实验2_241220051_沈思涵/` 结构打包。本轮不改写既有提交暂存目录，不生成最终提交 ZIP，不上传 cslab-cms。
